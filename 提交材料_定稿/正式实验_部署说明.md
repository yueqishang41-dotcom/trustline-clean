## 一、部署链路

```
GitHub (yueqishang41-dotcom/trustline)  ──push──▶  Vercel（Git 集成自动部署）
                                                        │
                                                        ▼
                                   https://你的vercel域名/
                                   https://你的vercel域名/api/collect

```

- 代码推到 GitHub `main` 分支后，Vercel 会自动构建部署（`vercel.json` 已配置 `npm run build` + `dist` 输出）。
- `/api/chat`、`/api/collect`、`/api/export` 为三个独立的 Serverless Function，Vercel 自动路由，无需额外配置。

## 二、一次性配置（★关键，约 2 分钟）

### 1. 在 Vercel 创建 Blob Store 并配置 Token

数据保存在 **Vercel Blob**。不配置则被试数据**无法保存**，`/api/export` 也无法导出。

1. 登录 Vercel → 进入本项目 → **Storage** 选项卡 → **Create Database** → 选 **Blob**（免费额度足够）→ 创建。
2. 创建完成后，复制生成的 **`BLOB_READ_WRITE_TOKEN`**。
3. 进入项目 **Settings → Environment Variables**，添加：
   - `BLOB_READ_WRITE_TOKEN` = 上一步复制的 Token
   - `DEEPSEEK_API_KEY` = `sk-…`（应已存在；用于 AI 微调代理，勿公开）
4. 修改环境变量后需要 **重新部署**（Deployments → 最新一次 → Redeploy），或再推一次代码触发部署。

> 说明：Vercel 新项目默认 Blob Store 与项目绑定，Token 就是项目级密钥，放在环境变量即可被 `/api/collect`、`/api/export` 读取。

### 2. 校验（部署完成、Token 配好后）

在浏览器打开（需已有一个真实被试数据，或先用你自己完成一遍测试）：

```
https://你的vercel域名/api/export          → 应返回 CSV（含表头与数据行）
https://你的vercel域名/api/export?format=json → 应返回完整 JSON 数组
```

> 若 CSV 只有表头没有数据行，说明还没有被试提交过，属正常；若返回 `BlobStoreNotFoundError` 之类，说明 Token 未配好，回到第 1 步。

## 三、数据怎么收集与导出

### 被试端（无需任何操作，数据只进不出）

- 被试完成后，页面**自动静默上传**完整数据到 `/api/collect`（含：逐题作答、逐题得分、三大维度分、**全量行为日志**、切屏次数、大段粘贴次数）。
- 上传失败时数据自动暂存到浏览器 localStorage，下次打开页面自动补传，**绝不丢失、绝不弹下载**。

### 主试端（导出「同一张大表格」）

| 格式 | 地址 | 内容 |
|---|---|---|
| 宽表 CSV | `https://你的vercel域名/api/export` | 每人一行：被试信息 + 模块A逐题得分/行为标志/参考答稿/AI初稿/被试最终文本 + 模块B逐题 + 行为日志JSON（可直接用于 SPSS/Excel 与人工 Rubric 打分） |
| 完整 JSON | `https://你的vercel域名/api/export?format=json` | 全量原始数据，供 R/Python/SPSS 深入分析 |

- 表内 `Form_Type` = `正式卷`，可一键与预实验数据（`Form_A/B/C`）区分。
- `Behavioral_Logs_JSON` 列含全部行为事件（含 `regenerate_prompt` 微调、`view_evidence`、`view_template`、`page_blur` 切屏、`bulk_paste_detected` 大段粘贴等）。

## 四、本次修复的两个已知问题（预实验遗留）

1. **高峰时段 DeepSeek 失败 → AI 微调不可用**
   - 服务端 `api/chat.mjs`：上游快速失败（429/502/503/504/超时）自动重试 1 次；
   - 前端：客户端再兜底重试 3 次（递增退避），失败后**内联提示 + 重试按钮**，被试输入的微调要求不丢失，可改用手动编辑。
2. **AI 微调使用过却没记录在结果中**
   - 此前 `act_regen` 依赖组件内存（useRef），页面重挂载后丢失；
   - 现在「是否使用过」以 **行为日志与内存取并集** 判定，刷新/重挂载也不会漏记（`dsh-A1__act_regen` 等列恒准确）。

## 六、机考模式（防止被试切到其他页面/程序）

正式实验时被试用**主试的电脑**答题、主试会离开房间，需要把被试"焊"在测验页面。分两层：

### 1. 网页内锁定（已内置，无需配置）

点击「**开始工作**」按钮（被试信息填完、进入指导语后）即自动生效，直到完成页点「返回首页」才解锁：

| 手段 | 效果 |
|---|---|
| 全屏 | 隐藏地址栏/标签栏/任务栏，避免被试点开其他网址 |
| 快捷键拦截 | F12、Ctrl+W/N/T/R/S/P/U、Alt+←/→、Alt+F4 等一律无效（`Esc`/`F11` 退全屏会立刻自动回锁） |
| 禁止右键 | 右键菜单（含"在新标签页打开/查看源代码"）被禁用 |
| 关闭/刷新确认 | `beforeunload` 弹窗警告"数据会受影响"，防误关 |
| 离开记录+警告 | 切走再切回（或按 Esc 试图退全屏）→ 红色覆盖层「⚠ 检测到离开测试页面，该行为已被系统记录」，须点「返回答题」才能继续；切屏次数与行为日志（`page_blur`）照常计入导出表 |
| 兜底回锁 | 锁定期内任何点击都会尝试重新全屏 |

> 调试逃生口：网址后面加 `?kiosk=0`（如 `https://…/?kiosk=0`）可完全关闭网页锁，**仅主试本机调试用**；被试在全屏锁定中无法改网址，故不会误用。

### 2. 系统级锁定（最强方案，正式实验推荐）

网页锁**拦不住操作系统级快捷键**：`Alt+Tab`（切换程序）、`Ctrl+Alt+Del`（安全界面）、`Win` 键、`Alt+F4`（关闭浏览器）等仍可跳出。真正 100% 锁定需要用浏览器的 **kiosk 模式**。

Windows 11（Edge 已内置）最简单用法——双击仓库根目录的 `启动正式测验_机考模式.bat`：

```bat
@echo off
start msedge --kiosk --edge-kiosk-type=fullscreen --edge-kiosk-info=0 --no-first-run --no-default-browser-check https://你的vercel域名/
```

效果：Edge 进入纯 kiosk 窗口（无地址栏/无标签栏/无关闭按钮），全屏锁定，按 `Ctrl+Alt+Del` 或强制关机/重启才能退出——**主试离开房间后基本无解**。

备选（Chrome，需已安装）：

```bat
start "C:\Program Files\Google\Chrome\Application\chrome.exe" --kiosk --no-first-run https://你的vercel域名/
```

退出 kiosk：`Alt+F4`（部分版本无效）或直接 `Ctrl+Alt+Del` → 任务管理器结束浏览器进程。

> 建议：**网页锁 + 系统 kiosk 同时开**（即用 bat 打开，被试再点「开始工作」触发网页全屏/拦截层）。两层叠加后，能想到的离开路径基本都堵死了。
